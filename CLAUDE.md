# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Tickerbook: a personal, mobile-first stock watchlist dashboard. It's a static site (plain HTML/CSS/ES modules, **no build step, no npm, no framework**) hosted on GitHub Pages. Data is pre-fetched by a Python script running in GitHub Actions, not fetched live from the browser. The audience is a long-term investor learning the jargon, so plain-English explanations are a core feature, not decoration.

## Commands

```powershell
python -m venv .venv; .venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python scripts\fetch.py                                   # refresh every ticker in watchlist.json
.venv\Scripts\python scripts\fetch.py --action add --ticker NVDA --tag researching
.venv\Scripts\python scripts\fetch.py --action remove --ticker NVDA     # also: --action tag --ticker X --tag owned
.venv\Scripts\python -m http.server 8765                                # serve; open http://127.0.0.1:8765
```

There are no tests or linters. Verify UI changes by serving locally and viewing in a browser (headless Chrome screenshots work; see the gotcha below about phone widths). VOO prints several `HTTP Error 404 ... No fundamentals data` lines during fetch. That's expected (ETFs have no company financials).

## Architecture

**Data flow:** `watchlist.json` → `scripts/fetch.py` (yfinance) → `data/<SYM>.json` (one file per ticker, everything every tab needs), `data/_bench.json` (S&P 500 prices for the "vs market" comparison), `data/index.json` (tickers + tags + names), `data/last_request.json` (outcome of the last add/remove/tag request) → browser.

**`fetch.py` normalizes Yahoo's inconsistent units.** Some `info` fields are percents (`dividendYield` 0.72 = 0.72%, `netExpenseRatio`, `ytdReturn`, `debtToEquity`) and go through `pct()`. Everything in the JSON is a decimal. Equities and ETFs produce different shapes: `type: "EQUITY"` has `valuation/fundamentals/analysts/earnings/financials`, and `type: "ETF"` has `fund`. The frontend branches on `d.type` throughout.

**Peers and holdings.** `build_peers()` stores up to 8 of the largest companies in the same Yahoo industry (`yf.Industry(industryKey).top_companies`, skipping other share classes of the same company) as `d.peers`; peer `info` calls are cached per run. Yahoo returns only a fund's top 10 holdings, so plain S&P 500 funds (name matches "S&P 500", without words like growth/equal/leveraged) take their top 15 from SPY's free daily holdings xlsx (needs `openpyxl`) and record `fund.holdingsSource`. Both fail quietly back to the Yahoo data.

**SEC press release.** `sec_earnings_release()` reads the latest 8-K with Item 2.02 (EDGAR submissions → filing index → the EX-99 exhibit), strips the HTML, and keyword-picks guidance and one-off sentences plus the company's adjusted EPS into `d.filing`. It runs only when the `SEC_USER_AGENT` env var (a repo **variable** in Actions) is set, because the SEC requires a contact in the User-Agent; without it, or on failure, the previous file's `filing` is kept. Only sentences that end in a period and contain an amount ($, %, million/billion) are kept, which drops boilerplate and table labels. Some filings are Windows-1252, not UTF-8. Many companies (CHTR, MSFT, GOOG) don't print an adjusted EPS, so `adjustedEps` is often null. The Earnings tab shows "In the company's own words" only when `d.filing` has content; each sentence is turned into a plain-English point (tone icon, short tag, bold summary) by the pattern rules in `translateRelease()` in `analysis.js`, with the original sentence under "Their exact words". Sentences no rule matches are shown as-is, and points with the same tag and amount are shown once (releases repeat themselves). The text is untrusted, so it's rendered as text only.

**Insiders and cash uses.** `insider_trades()` stores the last ~400 days of Form 4 trades as `d.insiders.transactions` (`kind`: buy/sell/award/gift/exercise/other, classified from Yahoo's `Text`; names reordered from SEC's LAST FIRST form by `insider_name()`). Only open-market `buy`/`sell` count as opinion; `insiderSummary()` (12-month window) ignores grants. Yahoo's own `insider_purchases` summary counts grants as purchases, so it isn't used. `statement()` also keeps `netDebtIssued`, `acquisitions`, `stockIssued`, `stockComp` for `cashUses()` (the Financials "Where the cash goes" card); cash-flow rows are signed as on the statement (money out is negative).

**`fix_ttm()` overrides Yahoo's `freeCashflow`** with the sum of the last 4 quarterly statements (Yahoo's info value is unreliable, e.g. $3B for MSFT vs ~$60B actual). It also stores `sharesImplied = marketCap / price`, because `sharesOutstanding` can cover only one share class (GOOG). Use `sharesImplied` for per-share math.

**Daily `history` snapshots are built by us and carried forward.** Yahoo has no historical P/E or estimate data, so `fetch.py` reads the previous `data/<SYM>.json` and appends today's snapshot. Deleting or regenerating a data file loses that history.

**Frontend modules (`assets/`):**
- `app.js`: hash router (`#/`, `#/t/SYM/<tab>`, `#/learn`, `#/settings`), all page rendering, bottom sheets, the research/progress task. Uses a tiny `h()` DOM builder. Untrusted strings (names, headlines, firm names) must go in as text children, never `html:`.
- `analysis.js`: pure functions. Formatters, the green/amber/red signal checklist (`equitySignals`, `fundSignals`, with all thresholds inline), `overall()` scoring, the plain-English earnings story, and valuation. `valuationMethods()` returns 7 methods: (1) "Future profits" P/E, (2) "Cash it generates" DCF, (3) "What Wall Street expects" (the **median** target, discounted a year), (4) "Priced like its peers": peers' median EV/EBITDA × EBITDA − net claims ÷ shares, where net claims = Yahoo EV − market cap via `netClaims()`, (5) "Peers' price-to-profit" (peers' median forward P/E × EPS; also left out when debt > 50% of EV), (6) "Back to its usual price-to-profit" (median of fiscal-year-end P/Es from `pastPEs()`; left out when they swing > 2×), (7) "If it never grows" (a no-growth floor: after-tax operating profit ÷ (required return − 2%, or − 4% with heavy debt) − net claims; **never** in the average, shown as a floor). Peer methods are left out by default with < 4 usable peers or when the middle-half multiples differ by > 1.6×. Each method has a `plain` English sentence, `steps` (the math with numbers plugged in, shown in the UI), a `reason` when excluded, and a reverse-solved `implied` growth. `blend()` averages the included ones. Defaults (`valuationInputs`/`modelDefaults`) deliberately use **today's** P/E as the exit multiple, the analysts' 2-year compounded growth capped at 15%, and a 12% required return when net debt/EBITDA > 3.5. DCF is excluded by default when FCF < 50% of net income (heavy-capex years). `confidence()` and `explainSpread()` explain in plain English why the methods disagree. `debtPicture()` feeds the "How the debt is counted" card (it names methods by number, so renumbering means updating it). Valuation scale dots never stack: overlapping dots are layered by z-index (methods in the average in front, higher number on top), per the user. `ratingScore()` turns the analyst counts into a net score (strong buy +2 … strong sell −2) with labels like "Hold, leaning sell"; it replaces Yahoo's `recommendationMean`, which uses a different set of analysts. `judge(key, d)` places the company against a glossary term's rule of thumb (good/ok/bad); its thresholds must match the glossary `rule` text. `quarterScore()` grades the latest report on 5 checks (Earnings tab). `oneOffs(q)` breaks a quarter's `unusualItems` into Yahoo's line items (write-offs, restructuring, investment gains…) and an after-tax per-share cost; `oneOffMiss()` flags misses that cost explains (shown as "One-off", not a miss, and explained under Report history); `reportQuarter()` matches a report date to its statement quarter. `newsMood()` is a keyword heuristic, labelled as such in the UI. Generated sentences may mark key phrases with `**bold**`; `rich()` in `app.js` turns them into `<b>` text nodes, so render those strings through `rich()`, never `html:`. Sanity-check outputs against the market price after any change here.
- `charts.js`: hand-rolled SVG line/column charts with crosshair tooltips, re-rendered via ResizeObserver. Colors come from CSS custom properties (`var(--series-1)` etc.).
- `glossary.js`: `GLOSSARY` keys are referenced by `termBtn(key)` / `qmark(key)` / signal `term` fields across `app.js` and `analysis.js`. Adding a metric usually means adding a glossary entry too.
- `github.js`: browser-side GitHub API client for the Research feature.

**Research flow (browser → Actions → browser).** With a fine-grained token in localStorage, `github.js` POSTs a `workflow_dispatch` to `update.yml` with a random `request_id`. It finds its run by matching `[request_id]` in the workflow's `run-name`, then polls the `fetch` job's steps and maps step names to progress stages (`STAGES[].match`). Finally it reads `data/last_request.json` and the new data straight from the repo via the Contents API, skipping the Pages redeploy delay. **The step names in `update.yml` and `STAGES` in `github.js` must stay in sync**, as must the `run-name` format and the job name `fetch`. When a token is configured, `fetchJSON` in `app.js` reads all data via the Contents API instead of the Pages copy.

**Workflow (`.github/workflows/update.yml`):** one workflow handles schedule (weekdays 21:30 UTC), `workflow_dispatch` (dashboard research and manual runs) and push. The `fetch` job commits data with `GITHUB_TOKEN`. Pushes made that way don't trigger other workflows, so deployment is a `deploy` job in the same workflow (Pages source must be set to "GitHub Actions"). Inputs are passed to the script via `env`, never interpolated into `run:`, to avoid shell injection.

**Laptop one-screen layout.** `app.js` toggles `html.dash-on` at `(min-width:1100px) and (min-height:600px)`. Each tab builds its cards inside `grid(name, flow)` (`.cols.dash.dash-<name>`), and each card gets `card(title, { area })`. That sets a `--area` CSS variable, which only becomes `grid-area` under `html.dash-on`; setting `grid-area` directly breaks the phone layout. The per-tab `grid-template-areas` live in `styles.css`. `fitDash()` gives each non-flow `.dash` a **min-height** equal to the window (and `--dash-h`), so cards grow to show their full content rather than scrolling internally. The user explicitly disliked "windowed scrolling". Only long lists opt into inner scrolling, with `class: "scroll-full"` (max height = window) or `"scroll-half"`. Long lists otherwise show a first batch plus a "Show all" toggle (analyst rating changes: 15, in 3 columns, each with a left edge colored by the firm's current Buy/Hold/Sell rating; firm-specific rating words like Overweight/Sector Perform map to Buy/Hold/Sell via `RATING_GROUP`, with hover meanings in `RATING_WORDS`). The Valuation tab keeps the Bear/Base/Bull scenario buttons at the top and the sliders in a collapsed "Fine-tune the assumptions" section at the bottom (the user rarely tweaks them). Card content sits in `.card-body`, the scroll area, so sticky table headers stay flush. Earnings uses `grid("earnings", true)`, a flowing layout. The Earnings and Financials charts use fixed heights rather than `fill`, because the user found filled charts too big. Charts created with `fill: true` take their container's height in dash mode, and their SVG is absolutely positioned so it can't inflate the row. Cards with class `dash-hide` are hidden on laptop.

**Since you last looked.** Opening a ticker stores a small `A.fingerprint()` in localStorage (`stockdash.seen.<SYM>`: price, checklist score, next-year EPS estimate, median target, analyst net score, newest action/report/filing/insider dates). When the data's `updated` differs from the stored one, `A.changesSince()` lists what moved; the banner above the tabs keeps showing it (from `prev`) until "Got it", and home cards show "N new" for data not yet opened. Browser-only, never sent anywhere.

**Peers tab (`#/t/SYM/peers`, equities).** Compares the company with `d.peers.list` (Yahoo industry top companies). `peer_info()` in `fetch.py` stores the same `info` fields for each peer as the ticker's own data, so each `PEER_GROUPS` row in `app.js` has a `self(d)` and a `peer(p)` getter reading the same field, an `ok` filter for meaningless values, and a `better` direction (`null` = not ranked, e.g. beta). "Beats/lags most peers" = better/worse than ≥ 2/3 of peers with a usable value. Analyst rating here uses Yahoo's `recommendationMean` for everyone (it's the only field peers have). Labels use `termPlain()` (no rule-of-thumb thumb; this tab ranks against peers instead). The user asked for this in place of a watchlist-wide compare page.

**Drops from a peak.** `A.drawdowns()` computes the running "% below previous high" over the 5-year price history; the price chart's "Drops" toggle plots it (with the S&P 500 when "vs S&P 500" is on, `yMax: 0` caps the axis) and `dropStory()` writes the worst-drop sentences.

**Rule-of-thumb badges.** `renderTicker` sets the module-level `CUR` (cleared in `route()`), and `termBtn(key)` appends a thumbs-up / dash / thumbs-down badge from `A.judge(key, CUR)` for terms with a glossary rule. The popover and the glossary sheet show the same verdict (`judgeBox`).

**Hover popovers.** On `(hover: hover) and (pointer: fine)` devices, any element with `data-term="<glossary key>"` or `data-tip`/`data-tip-title` shows a popover (delegated listeners near the end of `app.js`). Clicking a term still opens the bottom sheet.

## Constraints to preserve

- **Privacy / CSP:** `index.html` has a strict CSP (`script-src 'self'`, `connect-src 'self' https://api.github.com`, no inline scripts), plus `noindex`/`no-referrer` meta tags and `robots.txt`. Don't add CDN scripts, web fonts, analytics or inline `<script>`. External links use `rel="noopener noreferrer"`. The user explicitly asked for no tracking.
- **Mobile first:** base CSS targets ~390px wide, with `min-width: 640px` and `960px` breakpoints layered on top. Inputs stay ≥16px (prevents iOS zoom).
- **Charts follow the dataviz rules already applied:** a validated categorical palette (`--series-1..3`, light and dark values in `styles.css`), status colors (`--good/--warn/--bad`) only with an icon + word, never color alone, one y-axis per chart, a legend whenever there are ≥2 series, and text in ink tokens rather than series colors.
- **Dark mode** is defined twice in `styles.css` (the `prefers-color-scheme` block guarded by `:not([data-theme="light"])` and the `[data-theme="dark"]` block). Change both together.
- **Framing:** the score is a checklist tally, not a buy/sell call. Keep "not financial advice" disclaimers.

## Gotchas

- Headless Chrome on Windows won't lay out narrower than ~500px, so `--window-size=390,...` screenshots are misleading. To test phone width, load the app in a 390px-wide `<iframe>` from a page served over HTTP (not `file://`).
- Yahoo data is unofficial and sometimes inconsistent across endpoints (e.g. `calendar` vs `earnings_estimate`). Next-earnings estimates deliberately come from `earnings_estimate`'s `0q` row so they match the "What analysts expect" table.
- On Windows, read the JSON files with `encoding="utf-8"` (the default cp1252 fails).
- Use a fresh `--user-data-dir` for headless screenshots, or Chrome serves a stale cached `styles.css`.
- `Element.append()` stringifies arrays ("[object HTMLHeadingElement]"). Spread them; only the `h()` helper flattens arrays.
- In CSS, `html.dash-on .dash > .card` has high specificity, so overrides of card display/size in dash mode need an equally specific selector.
